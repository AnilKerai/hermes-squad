# Build your squad inside Claude Code

As of 10 October 2026, the most defensible way to build a personal coding squad with your own rules is to define it as plain files in the tool you already use: Claude Code subagents for roles, `AGENTS.md` and `.claude/rules/` for guidance, skills for procedures, hooks and permissions for anything that must never be violated, and a private plugin to carry the set between machines. Every alternative examined here either hands the actual coding back to a harness such as Claude Code or rebuilds one at considerable cost. Hermes Agent and NanoClaw do fit, but around the squad rather than as it: NanoClaw as a containerised dispatcher and scheduler you can message, Hermes as a durable multi-model task board, and both add security exposure, upgrade churn and metered spend. Squad orchestrators and methodology frameworks are best treated as donor libraries of role and skill files, and general-purpose agent frameworks earn their keep only when you need model independence or an unattended service. The measured evidence favours a small squad of one writer, read-only helpers and a fresh-context reviewer, at roughly 3–10x the tokens of a single agent, with your own review capacity as the binding limit. One fact that shapes every option beyond interactive sessions is unresolved: two research notes disagree on how Anthropic currently bills `claude -p`, the Agent SDK and third-party harnesses on a subscription, so verify that before committing to any always-on or headless design.

## Five routes exist, and four hand the coding back to a harness

A coding squad needs three things: a harness that edits files, runs commands, manages context and enforces permissions; some orchestration that sequences roles; and a home for your rules. The five families of options differ less in raw capability than in which of those layers they occupy. The table places each one, and the subsections explain the verdicts.

| Route | What it gives a squad | Where your rules live | Models | Verdict for a solo Claude Code user |
|---|---|---|---|---|
| Native Claude Code: subagents, skills, rules, hooks, plugins, workflows, Agent SDK | The harness, the roles and the enforcement | `AGENTS.md`/`CLAUDE.md`, `.claude/rules/`, `.claude/agents/`, skills, `settings.json` | Claude only | Backbone |
| Hermes Agent | Always-on runtime with a durable Kanban board of named profiles, cron and messaging | `SOUL.md`, one project context file, skills, `config.yaml` | Any provider or local model | Optional layer above the squad |
| NanoClaw and the OpenClaw family | Chat-reachable dispatcher and scheduler that hosts or launches a harness | Per-agent-group instructions (NanoClaw); per-agent workspace files (OpenClaw) | Claude by default, Codex or OpenCode per group (NanoClaw); many (OpenClaw) | Optional front door and quarantine |
| Squad orchestrators and methodology frameworks | Session management, or ready-made roles and workflows as Markdown | The underlying agent's own files | Whatever CLI they drive | Borrow files; skip swarms |
| General-purpose agent frameworks | A custom orchestrator, usually over harness workers | Your code, plus `AGENTS.md` and skills where supported | Any | Only for model independence or an unattended service |

### Native Claude Code turns a squad into version-controlled files

A role in Claude Code is a Markdown file with YAML frontmatter in `~/.claude/agents/` or a project's `.claude/agents/`. Each one carries its own system prompt, tool allowlist, model, effort level, permission mode, preloaded skills, MCP servers, hooks, optional persistent memory and optional `isolation: worktree` ([Sub-agents docs](https://code.claude.com/docs/en/sub-agents)). The runtime has moved on from the 2025 behaviour most tutorials describe: subagents now run **in the background by default, up to 20 at once, and nest three layers deep** from Claude Code v2.1.219 ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). A subagent starts with a fresh context holding its own prompt, the delegation message and the `CLAUDE.md` hierarchy, and returns only its final message to the caller, which is exactly the context boundary the evidence below rewards. One consequence matters for squad design: with Opus 5 on the standard preset, Claude Code instructs the model not to delegate unless asked, so a fixed plan-implement-review sequence has to be invoked explicitly by a skill or a workflow script rather than left to automatic delegation ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)).

The documentation draws a firm line between guidance and enforcement. `CLAUDE.md`, path-scoped `.claude/rules/*.md` files, skills and output styles are context the model is asked to follow; permissions, hooks and sandboxing are applied by the client whatever the model decides ([Memory docs](https://code.claude.com/docs/en/memory); [Permissions docs](https://code.claude.com/docs/en/permissions)). Guidance has a budget: Anthropic targets under 200 lines per `CLAUDE.md`, loads a rule carrying a `paths:` glob only when a matching file is touched, and since v2.1.277 reads `AGENTS.md` natively when no `CLAUDE.md` exists ([Memory docs](https://code.claude.com/docs/en/memory)). Skills keep only a short description in context and load their body on invocation, which makes them the right home for workflow procedures ([Skills docs](https://code.claude.com/docs/en/skills)). Enforcement is deterministic: permission rules evaluate deny, then ask, then allow, and hooks fire on about 30 lifecycle events, with exit code 2 blocking a tool call, a stop or a subagent's completion and feeding the reason back to the model ([Permissions docs](https://code.claude.com/docs/en/permissions); [Hooks reference](https://code.claude.com/docs/en/hooks)). A requirement that tests pass before the implementer finishes is therefore a `SubagentStop` hook, not a sentence in a rules file.

A plugin packages the squad. One directory ships agents, skills, hooks, MCP servers and workflow scripts, and a private git repository containing a `marketplace.json` installs it on any machine using the git credentials already present ([Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference); [Host a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace)). Two limits shape the design: a `CLAUDE.md` at the plugin root is not loaded, and plugin-shipped agents ignore frontmatter `hooks`, `mcpServers` and `permissionMode`. Always-on guidance therefore travels as a skill or a `SessionStart` hook, the pattern the Superpowers plugin uses, and enforcement lives in the plugin's `hooks/hooks.json` plus your own `settings.json` ([Sub-agents docs](https://code.claude.com/docs/en/sub-agents); [obra/superpowers](https://github.com/obra/superpowers)). For parallel work, `claude --worktree` and `isolation: worktree` isolate edits, background sessions dispatched from agent view move into their own worktree, and dynamic workflows run a saved JavaScript script of `agent()`, `parallel()` and `pipeline()` calls with 16 concurrent agents by default ([Worktrees](https://code.claude.com/docs/en/worktrees); [Agent view](https://code.claude.com/docs/en/agent-view); [Workflows](https://code.claude.com/docs/en/workflows)). Agent teams, which add a shared task list and teammate-to-teammate messaging, remain **experimental and off by default** and cost about **7x the tokens** of a standard session when teammates run in plan mode ([Agent teams](https://code.claude.com/docs/en/agent-teams); [Costs](https://code.claude.com/docs/en/costs)). They are an experiment to run, not a dependency to design around.

The Agent SDK is the same harness as a Python or TypeScript library. It reuses the same agents, skills, hooks and plugins while your code owns sequencing, approvals and hard budget caps such as `maxBudgetUsd` ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview); [Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). It becomes worthwhile when a pipeline must be deterministic, run from CI or cron, or sit inside your own tool; saved workflows now cover much of the scripted fan-out that once required it. The native route has two structural limits. It is single-vendor by policy, since Anthropic does not support routing Claude Code to non-Claude models through any gateway ([LLM gateways](https://code.claude.com/docs/en/llm-gateway)). And a squad kept only in `~/.claude/` does not follow you into cloud sessions or GitHub Actions, which work from the repository's own `.claude/` directory ([Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web); [GitHub Actions](https://code.claude.com/docs/en/github-actions)).

### Hermes Agent adds a durable task board on a fast-moving 0.x runtime

Hermes Agent is an MIT-licensed, self-hosted, always-on agent runtime that Nous Research released in February 2026, and it drives any model provider rather than requiring a Nous model ([The Next Web](https://thenextweb.com/news/nous-research-90m-1-5bn-hermes-agent-wsj); [Providers docs](https://hermes-agent.nousresearch.com/docs/integrations/providers)). On 10 October it showed **252.4k stars, version 0.21.6 and more than 5,000 open issues**, and the release of 8 October rolled up **2,106 pull requests merged in two weeks** ([GitHub repo](https://github.com/NousResearch/hermes-agent); [v0.21.6 release notes](https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.6)). That velocity is the central trade-off: features arrive weekly and so do regressions, including a September campaign to fix corruption in its state database ([GitHub releases](https://github.com/NousResearch/hermes-agent/releases)). Anyone building on it should pin a version.

Its customisation surface maps well onto personal rules. A profile is a separate home directory with its own `SOUL.md` persona, `config.yaml`, skills, memory and gateway process, so each squad member can be a profile ([Profiles docs](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)). Hermes reads `AGENTS.md`, `CLAUDE.md` and `.cursorrules` natively, but loads only one project context file per session, and `AGENTS.md` outranks `CLAUDE.md` ([Context files docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files)). A repository holding both will tell Claude Code and Hermes different things without warning, which argues for one canonical file. Skills follow the same agentskills.io format Claude Code uses, and the agent writes its own skills unless `skills.write_approval: true` forces human review ([Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). Built-in memory is capped at 2,200 and 1,375 characters across two files, so durable standards belong in context files and skills ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)). Whether Hermes offers deterministic lifecycle hooks comparable to Claude Code's was not established in the research; without them, compliance rests on prompts, approval modes and toolset restriction.

Hermes has two multi-agent mechanisms. `delegate_task` spawns anonymous, isolated subagents, 10 at a time by default, all on one configured delegation model ([Delegation docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)). Kanban is the more interesting: a durable SQLite task board shared across profiles, where named workers with their own persona, model and memory move tasks through a lifecycle with dependencies, git-worktree workspaces, review hand-offs to a chosen reviewer profile, and completion contracts that block a task until a pull request's required checks pass ([Kanban docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)). That is closer to an out-of-the-box team than Claude Code's subagents, because the workers are durable, named and auditable. It is also single-host and advances only while a gateway process is running, so a board on a laptop pauses when the lid closes.

On coding quality the evidence is real but partial. Claw-SWE-Bench, a set of 350 GitHub issue-resolution tasks, found Hermes had the highest pass rate of seven general-purpose harnesses on all three budget models tested, reaching **81.7% for $36 of total API cost** with DeepSeek-V4.1-Flash ([Claw-SWE-Bench](https://arxiv.org/pdf/2606.12344)). Claude Code, Codex CLI and OpenCode were not among the harnesses, so the result shows the Hermes loop is competent, not that it matches a dedicated coding agent. An independent comparison describes it as a generalist that stacks with Claude Code rather than replacing it for the minute-by-minute edit-test loop ([Hermes Atlas](https://hermesatlas.com/guide/vs-claude-code/)). Hermes ships a bundled skill that drives Claude Code through `claude -p` or a tmux-scraped interactive session, which is wrapper-level integration rather than a protocol ([claude-code skill docs](https://hermes-agent.nousresearch.com/docs/user-guide/skills/bundled/autonomous-ai-agents/autonomous-ai-agents-claude-code)). Security needs deliberate handling: the local backend has no sandbox, the docs state that the approval layer is not an operating-system sandbox, and a CVSS 8.8 flaw in versions 0.18.2 through 0.21.0 let a malicious repository's git configuration execute commands once opened ([Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security); [ReleaseAlert](https://releasealert.dev/cve/CVE-2026-71963)). Hermes belongs in the layer above the squad, handling scheduling, task state that spans days, cheap-model background work and notifications, with Claude Code kept for in-repo implementation.

### NanoClaw and OpenClaw are dispatchers you message, not squads

NanoClaw is an MIT-licensed TypeScript host process that routes messages from WhatsApp, Telegram, Slack, Discord and more than a dozen other channels to Claude Agent SDK sessions, each running in a Docker container per agent group, with per-group instructions, memory, scheduled tasks and a credential vault ([GitHub nanocoai/nanoclaw](https://github.com/nanocoai/nanoclaw); [nanoclaw.dev](https://nanoclaw.dev)). It is alive, with its first calendar-versioned stable release on 9 October 2026 and 30.9k stars, but it is no longer the 500-line project of its launch. A ground-up rewrite in April 2026 produced a codebase the project now puts at about **29,300 lines across 200 files** ([Changelog](https://docs.nanoclaw.dev/changelog); [nanoclaw.dev](https://nanoclaw.dev)). Because the project's philosophy is that customisation means changing your fork, its long run of breaking releases is a recurring merge cost.

Its squad model is one agent group per role, each with standing instructions composed into a `CLAUDE.md`, its own memory tree, container image, mounts and provider, with Claude as the default and Codex or OpenCode as alternatives ([Groups doc](https://docs.nanoclaw.dev/concepts/groups); [Providers doc](https://docs.nanoclaw.dev/extend/providers.md)). Isolation is the real attraction. Containers run unprivileged with all capabilities dropped and no access to the host home directory, extra mounts are denied by default and read-only unless both sides opt in, and credentials stay in a host-side vault that injects tokens into outbound requests so the container holds only a stub ([Security model](https://docs.nanoclaw.dev/concepts/security.md); [Credentials doc](https://docs.nanoclaw.dev/operate/credentials.md)). The project's own threat model assumes prompt injection will succeed and limits what a compromised agent can reach; it does not stop that agent from wrecking its workspace or misusing the credentials it was granted.

For coding, the documentation describes no squad workflow. The official GitHub integration makes an agent a participant in pull-request and issue comment threads and describes no clone, branch, push or open-PR capability ([NanoClaw GitHub skill](https://nanoclaw.dev/skills/github)). Agents talk to each other through `send_message` with no throttle, hop limit or cycle detection and no cap on simultaneous containers, and the maintainers have said they will keep the core minimal rather than build task routing ([Multi-agent guide](https://docs.nanoclaw.dev/guides/multi-agent-swarm.md); [GitHub discussion #1039](https://github.com/qwibitai/nanoclaw/discussions/1039)). In practice NanoClaw is headless Claude Code in a container that you can text. Branch conventions, review gates and test requirements have to be written into each group's instructions, in a second configuration universe alongside your repository's own.

That defines where it fits. NanoClaw adds real value in three places around a Claude Code squad: as an always-on inbox reachable from a phone; as a host for scheduled unattended jobs such as dependency checks, issue triage or PR-comment replies, where a hijacked job cannot read your Mac; and as quarantine for agents that must read untrusted content away from your main checkout. It is redundant when all you need is to nudge a running session or run a task on a timer, because Claude Code's own Channels (a research preview that needs the session to stay open), Remote Control, cloud sessions and routines cover that with fewer moving parts ([Claude Code channels docs](https://code.claude.com/docs/en/channels); [Routines](https://code.claude.com/docs/en/routines)).

OpenClaw is the giant of the family at 391.6k stars, now stewarded by an independent foundation ([GitHub openclaw/openclaw](https://github.com/openclaw/openclaw)). It has the most ready-made machinery for coding dispatch: ACP sessions launch Claude Code, Codex, Gemini CLI and other harnesses under the host's existing logins, and a small community plugin adds plan approval, a worktree per session and merge-or-PR outcomes ([OpenClaw ACP setup docs](https://docs.openclaw.ai/tools/acp-agents-setup); [goldmar/openclaw-code-agent](https://github.com/goldmar/openclaw-code-agent)). The price is exposure. Main-session tools run on the host unless sandboxing is configured, OpenClaw's sandbox cannot be enforced inside the native harnesses it launches, and its 2026 record includes a third-party skill caught exfiltrating data and a 2.0 release criticised for lacking filesystem and network boundaries ([OpenClaw ACP setup docs](https://docs.openclaw.ai/tools/acp-agents-setup); [Wikipedia](https://en.wikipedia.org/wiki/OpenClaw)). It suits only a developer who wants one chat front end across several vendors' coding harnesses and will run the gateway on a separate machine or VM. The lighter variants, among them PicoClaw, ZeroClaw, IronClaw, NullClaw and nanobot, compete on footprint, hackability or sandboxing and run their own tool loops against model APIs ([GitHub sipeed/picoclaw](https://github.com/sipeed/picoclaw); [GitHub zeroclaw-labs/zeroclaw](https://github.com/zeroclaw-labs/zeroclaw); [GitHub HKUDS/nanobot](https://github.com/HKUDS/nanobot)). They would not inherit your Claude Code rules, skills or hooks, and footprint is irrelevant on a developer Mac.

### Orchestrators and methodology plugins work best as donor libraries

Three kinds of tool sit on top of coding CLIs. Session managers run several agents side by side in git worktrees, which became the consensus isolation primitive ([Augment Code](https://www.augmentcode.com/tools/open-source-agent-orchestrators)). First-party products absorbed the feature and the independents thinned out: the company behind Vibe Kanban shut down on 10 April 2026 after failing to find a business model ([Vibe Kanban shutdown post](https://vibekanban.com/blog/shutdown)). Claude Squad, an AGPL terminal UI that pairs a tmux session with a worktree per agent and shipped v1.0.20 on 20 August 2026, and Conductor, a free Mac app for Claude Code and Codex, remain active ([Claude Squad releases](https://github.com/smtg-ai/claude-squad/releases); [Morph](https://www.morphllm.com/comparisons/superset-vs-conductor-vs-emdash)). None has a rules or roles layer of its own. They launch whatever CLI you point them at, so the choice is a user-interface preference.

Swarm orchestrators automate decomposition, hand-offs and merge queues, and the independent reports are sobering. One week on Gas Town cost $3,000 at roughly $100 an hour, with agents committing straight to the main branch for four hours before a pull-request workflow was imposed ([DoltHub](https://www.dolthub.com/blog/2026-03-24-a-week-in-gas-town/)). Its author warned a reviewer against using it seriously and later reported that a behaviour change in a new model version stopped it converging ([Maggie Appleton](https://maggieappleton.com/gastown); [Simon Willison](https://simonwillison.net/2026/Aug/4/steve-yegge/)). An audit of Ruflo, formerly claude-flow, could not support its headline performance claims ([rywalker research](https://rywalker.com/research/claude-flow)). The patterns deserve study: a persistent external work queue, a merge queue and supervised roles. The systems do not deserve adoption.

Methodology frameworks are the closest match to configurable rules and best practices, because they are literally editable Markdown: roles and workflows shipped as skills, slash commands and subagent files, with state kept in repository files. Superpowers, an MIT skills-based plugin in Anthropic's marketplace, chains brainstorming, planning, test-first implementation by a fresh subagent per task and a two-stage review ([rywalker on Superpowers](https://rywalker.com/research/superpowers-skills-framework)). Spec Kit, at about 140k stars, and OpenSpec, at about 71k, add a spec layer for greenfield work and for changes to existing code respectively; BMAD supplies explicit product, architecture, development and QA personas; gstack ships 23 specialist roles; Compound Engineering adds a step that writes learnings back into the repository ([SDD Observatory](https://sddobservatory.com/frameworks/spec-kit/); [developertoolkit.ai](https://developertoolkit.ai/en/ecosystem/frameworks/spec-driven-frameworks/); [BMAD releases](https://github.com/bmad-code-org/BMAD-METHOD/releases); [rywalker on Compound Engineering](https://rywalker.com/research/compound-engineering-plugin)). Churn is the caution. The original GSD repository was archived in June 2026 at 64.6k stars, Agent OS cut roughly 70% of its code in v3 to concentrate on injecting standards, and a hands-on comparison concluded that no single framework covers everything ([Pulumi](https://www.pulumi.com/blog/claude-code-orchestration-frameworks/); [Agent OS v3 discussion](https://github.com/buildermethods/agent-os/discussions/310)). Copy the role and skill files you like, trim them, and own the result.

Two layers of that content are portable. `AGENTS.md`, used by more than 60,000 open-source projects and stewarded by the Agentic AI Foundation under the Linux Foundation, is read by Codex, Cursor, Copilot, Gemini CLI and, natively, Claude Code; Agent Skills folders are read by a similarly long list of clients ([agents.md](https://agents.md/); [agentskills.io](https://agentskills.io/home)). Role definitions are not portable: Claude Code uses Markdown in `.claude/agents/`, Codex CLI uses TOML in `.codex/agents/`, and OpenCode uses Markdown in `.opencode/agents/` with a per-agent model override ([Daniel Vaughan](https://codex.danielvaughan.com/2026/04/27/codex-cli-custom-agent-definitions-toml-specialised-subagents/); [OpenCode docs](https://opencode.ai/docs/en/agents/)). OpenCode is the strongest base if a model-agnostic squad ever becomes a hard requirement.

### General frameworks now wrap coding harnesses instead of replacing them

LangGraph, CrewAI, Microsoft Agent Framework, the OpenAI Agents SDK, Google ADK, Pydantic AI, Mastra and the Vercel AI SDK are all actively shipping. AutoGen is the notable exception, in maintenance mode, with Microsoft Agent Framework, generally available since 3 April 2026, as its successor ([microsoft/autogen](https://github.com/microsoft/autogen); [Microsoft devblog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). The telling development of 2026 is that framework vendors conceded where coding competence lives. Mastra added an `AcpAgent` in June so a supervisor can delegate to Claude Code, Codex CLI or Gemini CLI, on the grounds that those harnesses bring the file editing, shell execution and test loops a framework user would otherwise have to build ([Mastra blog](https://mastra.ai/blog/introducing-agent-client-protocol)). Vercel's AI SDK 7 added a `HarnessAgent` for the same purpose, and Microsoft's 1.0 release listed a Claude Code SDK integration in preview ([Vercel AI SDK 7](https://vercel.com/blog/ai-sdk-7); [Microsoft devblog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). Others grew harnesses of their own, including LangChain's Deep Agents, OpenAI's `SandboxAgent` and Pydantic AI's Harness ([Deep Agents overview](https://docs.langchain.com/oss/python/deepagents/overview); [OpenAI sandbox guide](https://openai.github.io/openai-agents-python/sandbox/guide/); [Pydantic AI docs](https://pydantic.dev/docs/ai/overview/)). A source-code study of eleven coding-agent runtimes found that none imports a general-purpose agent framework ([arXiv 2609.00006](https://arxiv.org/abs/2609.00006)).

The reason is that harness quality is a first-order variable. LangChain lifted Deep Agents from 52.8% to 66.5% on Terminal-Bench 2.0 with the model held fixed, by changing only prompts, verification middleware and loop detection ([LangChain blog](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)). A working edit loop takes under 400 lines ([Thorsten Ball](https://ampcode.com/how-to-build-an-agent)); matching Claude Code on real repositories means sustained work on context management, edit reliability, permissions and per-model tuning, against vendors who release almost daily. Integration surfaces also break underneath you: OpenAI's Codex documentation now states that the `codex mcp-server` command, the basis of a widely copied multi-agent pattern, has been removed ([OpenAI Codex docs](https://learn.chatgpt.com/docs/mcp-server)). Durable-execution engines add a server to operate and assume remote sandboxes; Temporal's Agents SDK integration does not support local shell tools ([Temporal docs](https://docs.temporal.io/develop/python/integrations/openai-agents)). On one Mac, git plus Markdown task files is checkpointing enough.

A framework build is justified for a solo developer in four situations: model independence per role is a hard requirement, the squad must run unattended as an event-triggered service with an audit trail, full visibility of context is the goal in itself, or the build is the point. For personal rules, roles and review gates on your own repositories it is overkill. If you do go there, the lowest-regret shape is a thin orchestrator over harness workers, as in the documented pattern of LangGraph nodes that each call the Claude Agent SDK, whose author lists two layers to debug, accumulated latency and growing state as the costs ([Khaled Elfakharany](https://www.khaledelfakharany.com/articles/langgraph-claude-sdk-integration)).

## Measured evidence backs one writer with read-only helpers

The research on multi-agent systems is consistent enough to design from, with one caveat: no controlled study of late-2026 models on real repository work was found. A Google Research, DeepMind and MIT study spanning up to 260 configurations found that adding agents changed results by anywhere from **+80.8% on decomposable tasks to −70.0% on sequential planning**, that independent agents amplified errors 17.2x against 4.4x for a centralised design, and that coordination stopped paying once a single agent already succeeded about 45% of the time ([arXiv 2512.08296](https://arxiv.org/abs/2512.08296); [Google Research blog](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)). The Berkeley-led MAST analysis of more than 1,600 traces across seven multi-agent frameworks recorded failure rates of 41% to 86.7%, driven by organisational design and coordination rather than weak individual agents ([arXiv 2503.13657](https://arxiv.org/abs/2503.13657)). Anthropic's own guidance puts multi-agent work at 3–10x the tokens of a single agent on an equivalent task and reports that agents split by job title into planner, implementer, tester and reviewer spent more tokens coordinating than working ([Claude blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)). Cognition, once the loudest critic, now says multi-agent systems work when writes stay single-threaded and the extra agents contribute intelligence rather than actions ([Cognition](https://cognition.com/blog/multi-agents-working)). Anthropic's August 2026 research shows both halves: a coordinated 45-agent swarm found 266 vulnerabilities against 21 for independent agents, yet in a shared-repository build 18 of 30 agents chose the identical branch name ([Anthropic](https://www.anthropic.com/research/multiagent-systems)). Multi-agent earns its cost on search, exploration and review, not on concurrent implementation.

The reliable roles are therefore defined by context boundary, not job title. Read-only explorers that search and summarise in a separate context window are endorsed by Anthropic's documentation and by practitioners ([Claude Code best practices](https://code.claude.com/docs/en/best-practices); [Simon Willison](https://simonwillison.net/guides/agentic-engineering-patterns/subagents/)). A fresh-context reviewer is the other well-supported helper: Cognition reports its clean-context review agent catching an average of two bugs per pull request, more than half of them severe, though Anthropic warns that a reviewer told to find gaps will usually report some, so it should flag only correctness and requirement gaps ([Cognition](https://cognition.com/blog/multi-agents-working); [Claude Code best practices](https://code.claude.com/docs/en/best-practices)). Reviewer strength matters more than reviewer diversity. In a July 2026 study a strong model reviewing a weaker one gained 18.1 points, while a weaker model reviewing a strong one lost 8.6 points by rewriting code that already passed ([arXiv 2607.21656](https://arxiv.org/abs/2607.21656)). An October 2026 study found that on code, same-model fresh-context review beat every cross-model condition ([arXiv 2610.01471](https://arxiv.org/abs/2610.01471)). Parallel implementers are conditional on independent tasks and a strong oracle: Anthropic's 16-agent C compiler build cost about $20,000, hit frequent merge conflicts, and parallelised well only once a reference compiler let agents fix different bugs in different files ([Anthropic C compiler](https://www.anthropic.com/engineering/building-c-compiler)).

On rules, the one rigorous study cuts against the instinct to write a lot. ETH Zurich found that LLM-generated context files slightly reduced task success and raised cost by about 20%, while developer-written files improved success by about 4% on average; agents do obey these files, so every unnecessary line costs steps and money ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988)). Instruction-following degrades with volume, with the best frontier models reaching only 68% accuracy at 500 simultaneous instructions ([arXiv 2507.11538](https://arxiv.org/abs/2507.11538)). Anthropic's guidance matches: delete any line whose removal would not cause a mistake, and use hooks for anything that must happen every time ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). In a squad the budget multiplies, because every subagent inherits the always-loaded file.

Verification is the lever everyone agrees on, and tests alone are measurably insufficient. In SWE-Gate, **221 of 644 test-passing agent repairs failed constraints drawn from real review comments**, and even the best automated review combination in the October study found only 56.7% of planted errors ([arXiv 2609.04167](https://arxiv.org/abs/2609.04167); [arXiv 2610.01471](https://arxiv.org/abs/2610.01471)). That leaves you as the final gate, and your throughput is the ceiling. METR's 2025 trial found experienced developers 19% slower with AI tools, and its 2026 follow-up produced estimates whose confidence intervals include zero and which METR itself treats as unreliable ([METR 2025](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/); [METR 2026](https://metr.org/blog/2026-02-24-uplift-update/)). An Anthropic trial found that engineers who learned a library with AI help scored 17% lower on comprehension ([Anthropic](https://www.anthropic.com/research/AI-assistance-coding-skills)). Practitioners range from Mitchell Hashimoto's single background agent to Boris Cherny's five terminal sessions plus five to ten web sessions ([Mitchell Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey); [InfoQ](https://www.infoq.com/news/2026/01/claude-code-creator-workflow/)). For a solo owner with no second human who understands the code, one closely supervised stream plus two to four low-review-cost background streams is the realistic limit.

Security evidence points to architecture over filtering. No single agent session should combine private data, untrusted input and an outbound channel ([Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). Human approval is not a boundary, since Claude Code users approve 93% of permission prompts, and third-party extensions are a live supply-chain risk: Snyk found security flaws in 36.82% of 3,984 public agent skills and 76 confirmed malicious payloads ([Anthropic on auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode); [Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)). Scaffolding also goes stale. Anthropic removed whole stages from its planner-generator-evaluator harness when a newer model made them unnecessary ([Anthropic harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Keep orchestration thin and in plain files, and re-test what still earns its cost at each model upgrade.

## Headless and third-party subscription billing remains unresolved

The economics of everything beyond an interactive session depend on one rule, and the research behind this report contains two incompatible accounts of it. Both agree on the first half of 2026. From 4 April, Claude subscriptions stopped covering third-party harnesses such as OpenClaw ([Cybersecurity News](https://cybersecuritynews.com/claude-ends-openclaw-subscriptions/)). In mid-May Anthropic announced that from 15 June programmatic use, meaning `claude -p`, the Agent SDK, Claude Code GitHub Actions and third-party apps authenticated through the SDK, would move to a separate monthly Agent SDK credit billed at API rates, set at $20 for Pro, $100 for Max 5x and $200 for Max 20x ([Zed blog](https://zed.dev/blog/anthropic-subscription-changes); [The Register](https://www.theregister.com/ai-ml/2026/05/14/anthropic-tosses-agents-into-the-api-billing-pool/5240748)).

They diverge on what happened next. The first account, from the Hermes research, treats that split as having taken effect on 15 June 2026, so headless and SDK usage no longer draws on the interactive pool and is capped by a credit that does not roll over ([The Register](https://www.theregister.com/ai-ml/2026/05/14/anthropic-tosses-agents-into-the-api-billing-pool/5240748); [env.dev](https://env.dev/updates/anthropic-agent-sdk-credits); [claudefa.st](https://claudefa.st/blog/guide/development/agent-sdk-credit)). It rests on search-result summaries of press and blog coverage; Anthropic's own pages were not opened. Hermes's documentation adds a narrower claim of its own: its Anthropic OAuth path works only on a Max plan with purchased extra-usage credits, and Pro subscribers must use an API key ([Providers docs](https://hermes-agent.nousresearch.com/docs/integrations/providers)). The second account, from the NanoClaw research, says Anthropic paused the change on the day it was due and promised a revised plan with advance notice, that the current help-centre article states Agent SDK, `claude -p` and third-party app usage still count against ordinary subscription limits, and that since 7 October 2026 Max and Team plans additionally include monthly API credits covering the Agent SDK, `claude -p`, the Claude API and Managed Agents ([Anthropic help centre](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan); [Zed blog](https://zed.dev/blog/anthropic-subscription-changes)). It rests on a fetched Anthropic help-centre page, though the credit amounts of $100 for Max 5x and $200 for Max 20x come only from secondary reports ([pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/21541/anthropic-claude-max-team-api-credits)). A third-party timeline updated on 9 October says no revised plan had been announced since June, which fits neither account cleanly ([BetterClaw](https://www.betterclaw.io/blog/openclaw-anthropic-subscription-ban)). Separately, the Agent SDK documentation bars third-party developers from offering claude.ai login in products built on the SDK, and the research found no explicit statement either way about a solo developer running the SDK against their own subscription ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)).

This report does not resolve the conflict, and you should not design as though it were resolved. Before committing to Hermes driving `claude -p`, NanoClaw on a subscription token, scheduled headless scripts, a subscription-authenticated GitHub Action or an Agent SDK orchestrator, read Anthropic's help-centre article on using the Agent SDK with a Claude plan, run a short headless job and check how your own account meters it, and re-read the Hermes providers page. Three things hold under either account. Interactive Claude Code sessions, including their subagents, skills, hooks and workflows, stay on the subscription. The rule moved several times during 2026 on either telling, so any always-on design should budget for API-rate billing as the fallback. And if headless use does share the subscription pool, an overnight squad competes with your daytime work for the same rolling five-hour and weekly windows ([Costs](https://code.claude.com/docs/en/costs)).

## Start with one rules file, three subagents and a stop hook

The recommended stack has a core that is safe under every uncertainty above and optional layers added only when a concrete need appears. The core is Claude Code configured as files. The first optional layer is first-party reach: background sessions, cloud sessions and routines. The second is a third-party runtime, either NanoClaw for containerised chat and scheduled jobs or Hermes for a durable multi-model board. Code, meaning the Agent SDK or a thin orchestrator, comes last.

Begin with the rules, because they outlive every tool choice. Write one short, hand-authored `AGENTS.md` per repository, limited to commands the agent cannot guess, non-default conventions, test instructions and known gotchas, and let Claude Code read it directly or import it from a thin `CLAUDE.md` ([Memory docs](https://code.claude.com/docs/en/memory); [Claude Code best practices](https://code.claude.com/docs/en/best-practices)). Put cross-project standards in `~/.claude/rules/`, detail for parts of a codebase in path-scoped `.claude/rules/` files, and each repeatable procedure, such as how you plan, review or write a migration, in a skill. Then convert every rule that says must into something executable: a linter or test where possible, otherwise a permission deny rule or a hook.

Define three subagents by context boundary. An explorer is read-only, runs on a cheap model and returns a short summary of where things are and how they work. An implementer is the single writer, isolated in a worktree, and owns the tests for the feature it builds, as Anthropic's context-centric guidance recommends ([Claude blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)). A reviewer is read-only, runs on your strongest model, receives the spec and the diff but not the implementer's reasoning, and reports correctness and requirement gaps without rewriting anything. Planning needs no agent of its own: plan mode and a planning skill that writes a spec naming the files involved, what is out of scope and the final verification step do the job ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). Model tiering is the main cost lever you control, with Haiku 5.5 listed at one-fortieth of Opus 5.5's input price, but the review studies say not to economise on the reviewer ([API pricing](https://platform.claude.com/docs/en/about-claude/pricing)).

Add one gate before adding anything else: a `SubagentStop` or `Stop` hook that runs the test suite and linters and blocks with the failure output, plus a `PreToolUse` rule that stops the implementer from editing the tests and gate scripts it is judged by without your sign-off. Then write one orchestration skill, invoked as a slash command, that names the stages in order: explore, write the spec, pause for your approval, implement in a worktree, run the gates, review in a fresh context, and summarise the evidence. This keeps the squad a workflow in a single thread, which is the shape the evidence supports, and it makes delegation explicit, which current model behaviour requires. When the sequence stabilises, save it as a dynamic workflow so it runs in the background ([Workflows](https://code.claude.com/docs/en/workflows)).

Once those files have survived a couple of weeks of real work, move them into a private GitHub repository that is both marketplace and plugin, load it from a local path while you iterate, and install it on other machines with `claude plugin marketplace add` ([Create a marketplace](https://code.claude.com/docs/en/plugins/create-marketplace)). Commit a copy of the agents and skills to any repository you want cloud sessions or GitHub Actions to work on. Keep a small regression set of 10 to 30 past tasks from your own repositories and re-run it whenever you change a rule, skill or hook, because single runs of a stochastic agent prove nothing; `claude plugin eval` exists for exactly this ([Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)). Scale parallelism last, to two to four background or worktree sessions on well-specified, low-review-cost tasks, and treat agent teams, parallel implementers, overnight loops and a second-vendor reviewer such as Codex CLI as experiments to measure against that regression set.

Add an outside runtime only when the squad needs to work while you are away from the keyboard and first-party routines and cloud sessions fall short. Choose NanoClaw when the need is a phone-reachable inbox or scheduled jobs that read untrusted content. Give each trust level its own agent group, mount repositories read-only by default, issue fine-grained tokens through the vault, and require branch protection and human PR review, since its documentation supplies no loop or concurrency limits ([Security model](https://docs.nanoclaw.dev/concepts/security.md); [Multi-agent guide](https://docs.nanoclaw.dev/guides/multi-agent-swarm.md)). Choose Hermes when the need is a task board that spans days and mixes cheap models for background work: one profile per role, Kanban with worktree workspaces and completion contracts, `skills.write_approval` switched on, workers in the Docker backend, a pinned version and an API-key budget ([Kanban docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban); [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)). Skip OpenClaw unless you want one chat front end over several vendors' harnesses and can isolate it on another machine. Reach for the Agent SDK when you want the same squad as a deterministic, budget-capped pipeline in CI, and for a general framework only if model independence becomes non-negotiable. In every one of these cases, settle the billing question first.

## Conclusion

The squad you are designing is content, not a runtime. Roles, rules and procedures written as Markdown agents, `AGENTS.md` and skills are read by Claude Code today and, with small format changes, by Hermes, NanoClaw, Codex, OpenCode and the frameworks that now wrap them; only the hooks, permissions and workflows are specific to Claude Code. That inverts the usual build decision. Choosing a platform matters less than keeping the rule set short, the gates executable and the test oracle under your own control, because those are what every runtime leans on.

Two things will change under you. Models will make parts of the scaffolding redundant, so the measure of a mature squad is how much of it you have deleted after each upgrade, not how many agents it runs. And Anthropic's billing rules for headless and third-party use are still moving, which makes the question of whether a component can run inside an interactive session a useful test until you have verified the current policy yourself. Nothing in the evidence gathered here suggests a larger swarm will beat three roles and one gate that you can actually review.
